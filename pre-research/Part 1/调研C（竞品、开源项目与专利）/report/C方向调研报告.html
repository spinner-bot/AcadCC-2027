0. 一页结论

已经站得住的三条

  1. 开源侧「三单匹配 + 归因」几乎没有生产级项目——中英双语检索互证，结果稳定
  2. 存在 1 个高度重合的公开 demo，已完成源码级核验；它没有做结构化电子凭证，也没有账套对接
  3. 底层文档解析已成熟，不应自研；但 MinerU 的许可需要读原文

还不能用的三条

  1. 商业竞品能力矩阵：6/13 家已做公开页核验；P0 已查看 48/117，其中有直接支持证据 8/117。每刻、合思已有直接三单/四单证据；金蝶、汇联易公开页关键项未见说明
  2. 专利：中英文初筛完成，中国 49 条记录中已核 8 件 claim1；但国知局登记簿、同族、审查档案和 FTO 尚未完成
  3. 「国内厂商 AI 归因弱」：纯推断，未取证，不得写入正式材料

最需要纠正的一条口径

  1. 「竞品只标记不解释」不成立。leokcgchen 的代码里有 riskReason、ReasoningStep 推理链和 bbox 溯源。正确表述是「规则级解释 + 过程留痕，未到证据驱动归因」。

3. 有效性评估

3.1 内部效度（结论是否由证据推出）

  • 关键词检索只能证明「搜不到」，不能证明「不存在」。这一条对中英文都成立，只是英文更干净。
  • 未使用代码搜索。GitHub code search 需要登录，本轮只搜了仓库名与描述，可能漏掉不叫 three-way-match 的实现。
  • 中文切词差，中文检索结果噪声大，所以中文侧结论更弱。
  • star 数不等于可用性：188 个仓库里 0–3★ 多为课程作业；反过来，AWS 315★ 也只是参考架构，不是产品。

3.2 外部效度（能否推广）

  • 开源空白 ≠ 商业空白。商业侧恰恰相反：三单匹配是 ERP 的标配功能。这两条绝不能混着讲，否则会得出「市场没有竞品」的错误结论。
  • GitHub 生态 ≠ 中国市场。国内厂商代码不公开，开源结论对国内商业竞争解释力有限。
  • 学生 demo ≠ 技术前沿。leokcgchen 是个人项目，不代表行业水平。

3.4 可靠性
