# 商业竞品分层（国内外）

> 2026-10-17　定位与分层为行业共识级判断；具体功能、版本、价格**均需回官方文档核实**，不得直接引用本页。

## 先说三个结论

1. **三单匹配在商用产品里是标配**，不是差异点。任何一家 ERP 的应付模块都有，不能拿"我们能做三单匹配"当创新。
2. 商用产品的差异集中在四件事：单据采集（IDP）、容差与审批流、ERP 集成、当地合规（Peppol / ZUGFeRD / 数电票）。
3. 真正可能站住的位置是"**异常之后那一步**"：归因、字段级证据链、复核流。这是本页要重点核的方向。

## 第一层：国际 ERP 套件（能力最全，实施最重）

| 厂商 | 相关模块 | 备注 |
|---|---|---|
| SAP | S/4HANA 应付 + Ariba 采购 | 发票校验、容差、三单匹配；deck 第 61 页已引其 Help 文档 |
| Oracle | Fusion Cloud ERP · Payables | 有 match approval level 概念（2/3/4 方匹配），需核具体版本 |
| Microsoft | Dynamics 365 Finance | 发票匹配与采购订单/收货联动 |
| Infor / Workday | 财务模块 | 大型企业，国内存在感弱 |

**对你们的意义**：定义了"企业级基线"，但价格与实施门槛把中小企业挡在外面。这也解释了为什么国内 SaaS 有生存空间。

## 第二层：国际 AP 自动化 / P2P 专业厂商（最直接的功能对标）

- **P2P 套件**：Coupa、Basware、Ivalua、JAGGAER
- **发票处理 / AP 自动化**：Medius、Esker、Tungsten Automation（原 Kofax）、Stampli、Yooz、Tipalti
- **账单与支付**：Bill.com、Ramp（偏中小企业）

**特点**：发票匹配、审批流、供应商门户是核心卖点，普遍支持多币种、多语言、多国税制。
**对你们的意义**：如果说"差异点在归因与证据链"，这批产品是最需要逐个核对的对象。

## 第三层：AI 原生厂商（最需要警惕的新进入者）

| 厂商 | 定位 | 要核的问题 |
|---|---|---|
| Vic.ai | AP 自动化，AI 记账与审批 | 判断是否可解释、能否给出依据 |
| AppZen | 费用与审计 AI | 是否做异常归因，还是只做风险打分 |
| HighRadius | 应收、财资、AP 自动化 | 是否有证据链 |
| Auditoria.ai | 财务后台 AI 助手 | 同上 |
| Hyperscience | 智能文档处理（IDP） | 只做抽取，还是延伸到核验 |

**为什么最危险**：它们卖的正是"AI 判断"，与你们的假设最接近；而且叙事能力强，评审容易觉得"这个已经有人做了"。
**必须核清的**：它们是**给结论**，还是**给结论 + 依据 + 可复核路径**。这决定你们的差异点还成不成立。

## 第四层：国内厂商（票据生态强，AI 归因弱）

| 类别 | 厂商 | 与本项目的关系 |
|---|---|---|
| ERP | 用友（BIP / YonSuite）、金蝶（苍穹 / 云星空）、浪潮、远光 | 应付模块自带匹配，客户基数大 |
| 费控 / 财务共享 | 汇联易、每刻、合思（易快报）、元年科技、汉得、中兴新云 | 最接近"财务人员日常使用"的场景 |
| 票据 / 税务服务 | 云砺（票易通）、百望云、航天信息、高灯科技 | 做发票查验、归集、归档，不做业务勾稽 |
| RPA / IDP | 实在智能、来也、艺赛旗 | 从自动化往上做，可能切入核验 |

**国内厂商的真实优势**：数电票生态、税局对接、电子归档合规、本地实施。
**普遍薄弱**：跨单据的业务勾稽、异常归因、可解释性。**这一点必须核实，不能当成想当然。**

## 谁是真竞品（按重叠度排序）

| 对象 | 重叠点 | 差异点 | 威胁 |
|---|---|---|---|
| SAP / Oracle 应付模块 | 三单匹配、容差、审批流 | 重实施、贵、归因弱 | 中（客户群不同） |
| Coupa / Basware / Medius / Esker | 发票匹配 + AP 自动化 | 全球合规强，中文数电票弱 | 中 |
| 用友 / 金蝶 | 应付匹配、票据、账套 | AI 归因与证据链弱 | 高（同市场、同客户） |
| 汇联易 / 每刻 / 合思 | 费控场景、发票归集 | 偏报销，不做采购三单 | 中高 |
| 云砺 / 百望云 | 发票查验、税务协同 | 只验真伪，不做业务勾稽 | 中（可互补） |
| Vic.ai / AppZen | AI 判断 | 国内落地弱、中文票据弱 | 高（叙事上） |

## 对 C 的下一步：只深访三家

不要 12 家都浅尝。C 的产出是差异点，不是厂商大全。建议：

1. **1 家 ERP**（SAP 或 Oracle）：确认"企业级基线"到底到哪一步
2. **1 家国际 AP 专业厂商**（Medius 或 Esker）：确认"匹配之后"的交互与归因
3. **1 家国内费控/票据厂商**（汇联易、每刻或云砺）：确认中文数电票场景的真实能力

每家只问五个问题：

- 三单匹配是逐行还是总额？容差怎么配？
- 差异产生后，系统给的是"标记"还是"原因"？
- 结论能不能点到原始单据的具体字段？
- 有没有人工复核留痕？能不能导出审计底稿？
- 能不能直接吃数电票 XML/OFD，还是只能 OCR？

这五个问题答完，差异点是否成立就有答案了。
