# 中国专利补充核验

> 核验日期：2026-10-18  
> 检索入口：Google Patents 中国专利全文页（页面含 CN 公开文本、权利要求和法律状态时间线）  
> 本轮完成：中文关键词检索命中 49 条公开记录；对其中 8 件直接/相邻相关专利读取了首项权利要求和法律状态  
> 未完成：国知局官方登记簿、审查档案、同族、权利转移、无效/诉讼记录；因此本文件是**初筛**，不是 FTO 法律意见

## 一页结论

**能查，而且国内专利并不是空白。** 上一轮的问题不是“没有中国专利”，而是只做了英文检索，中文结果没有入库。

本轮最重要的三个发现：

1. **“三单匹配”在中国已有授权专利**：`CN112131470B`（欧冶云商，2024-03-12 授权，Active）的权利要求 1 覆盖“发票 + 货物清单 + 业务类型/匹配模式 + 线性最优匹配 + 生成结算单”。
2. **合思的供应商结算系统把“应付三单匹配 + 发票查验 + OCR + 预制发票确认 + 发起开票”写进了系统权利要求**：`CN116596607A`（申请中，Pending）。这既是商业竞品证据，也是本项目最需要盯住的专利。
3. **“数电发票 + 行项目匹配 + 价格容差 + 生成应付发票”也已被主张**：`CN119850353B`（长飞光纤，2025-10-10 授权，Active）。如果我们的实现落在这条链路上，不能把它当作新颖点。

直接结论：**本项目不能把“三单匹配”“发票 OCR/查验”“数电发票直读”“行级匹配 + 容差”单独写成创新点。** 还能争取的空间，必须落到“跨单据的证据组织、字段级定位、矛盾归因、人在环复核”这些更具体的技术特征上。

## 关键权利要求摘录与影响

### 1. `CN112131470B`：三单匹配已被授权

- 申请日：2020-09-23；公开日：2020-12-25；授权日：2024-03-12；预计届满：2040-09-23。
- 权利要求 1 的核心步骤：
  > 获取待匹配供应商发票和货物清单……根据业务类型和匹配模式，通过线性最优进行匹配……从待匹配的货物清单中剔除已匹配的货物……生成结算单。
- 影响：它把“发票—货物清单”的最优匹配、业务类型分支和结算单生成写成了方法权利要求。它不直接覆盖我们所说的“采购订单—收货单—发票”三方结构，但足以证明**自动匹配 + 结算**不是新颖点。
- 风险：对“钢材/仓单/统购分销”场景更窄；对通用三单匹配是中高风险。

### 2. `CN116596607A`：合思把整条供应商结算链路写进 claim 1

- 申请日：2023-05-22；公开日：2023-08-15；状态 Pending。
- 权利要求 1（摘要）：
  > 企业端供应商结算系统和供应商端供应商结算系统……供应商结算业务处理至少包括：应付三单匹配、发票查验、OCR识别、预制发票确认和发起正式发票开具。
- 影响：这不是“疑似能力”，而是**竞争者在专利文本中明确主张的产品链路**。如果该申请按现有文本授权，系统层的覆盖会非常宽。
- 风险：**最高优先级监控对象**。竞赛叙事不能再把“三单 + 查验 + OCR + 开票”作为组合创新；商业落地前应让专利代理人评估规避设计。

### 3. `CN119850353B`：数电发票行级匹配 + 容差 + 应付发票

- 申请日：2024-12-25；公开日：2025-04-18；授权日：2025-10-10；状态 Active。
- 权利要求 1 的核心步骤：
  > 获取数电发票和采购接收事务；结合不含税单价、数量及预设的不含税单价允差，将每个发票明细行与接收事务行匹配；汇总不含税金额、税额、含税金额；在总含税金额尾差不超过预设允差时调整至少一个接收事务行，直至三者相等；根据调整后的匹配信息创建应付发票单据。
- 影响：这条把“数电发票明细行—采购接收行”的匹配、价格容差、金额尾差调整和应付发票创建连成了一条完整链路。
- 风险：如果我们的“数电票直读 + 自动配单 + 生成凭证/应付单”实现落在相同步骤上，**中高风险**。需要把“证据链 + 归因 + 人工复核”做成真正不同的技术路径，而不是仅换界面。

### 4. `CN114612201A`：发票校验 + 入库清单 + 凭证生成

- 申请日：2021-12-31；公开日：2022-06-10；状态 Pending。
- 权利要求 1 的核心步骤：
  > 获取验证成功的发票信息；调用入库清单底表字段；将入库清单字段与发票信息匹配；根据匹配结果对目标发票进行校验。
- 影响：它覆盖“验票—入库清单—匹配—校验”的基础流程，但未读到“三方单据 + 归因 + 字段级证据”的限定。
- 风险：中；可作为“自动凭证生成”现有技术证据，不能单独作为我们差异点。

### 5. `CN121052886A`：ERP 发票池 + 订单校验 + 报销/付款审批

- 申请日：2025-07-07；公开日：2025-12-02；状态 Pending。
- 权利要求 1 的核心步骤：
  > 获取数电发票，按订单编号将结构化数据和发票影像存入 ERP 发票池；用订单编号找到待校验数据；ERP 发票检验程序校验通过后，生成报销单和付款审批单。
- 影响：与“数电票 + 订单 + ERP + 报销/付款”高度重合，但限定在电力物资供应链场景。
- 风险：中高；如果产品面向电网/物资供应链，应重点规避。

### 6. `CN122416469A`：最接近“规则 + LLM + 置信度 + 人工复核 + 明细溯源”的一件

- 申请日：2026-05-30；公开日：2026-07-17；状态 Pending。
- 权利要求 1 的核心步骤：
  > OCR 提取多张医疗票据文本；分级规则匹配（精确、时空、金额）；规则无法确定时构造 prompt 交给大模型语义推理，输出可信度评分；记录规则、模型和人工复核结果，动态调整决策逻辑；将费用清单明细项目溯源到对应发票；供审核员复核。
- 影响：虽然对象是商保医疗票据，不是应付账款三单，但它的**技术组合**与本项目“规则 + 大模型 + 置信度 + 人在环 + 明细溯源”非常接近。若我们只换业务场景，审查员很可能拿它做现有技术。
- 风险：中高（创新性叙事）；商业化 FTO 风险取决于具体权利要求和领域解释。

### 7. `CN120833606A`：字段定位，不等于证据链

- 申请日：2025-07-04；公开日：2025-10-24；状态 Pending。
- 权利要求 1：构建“语义字段—引导词”字典；OCR 得到文本块位置与内容；识别候选引导词块；建立上下左右邻接关系；形成 `(S,N,D)` 语义锚点三元组。
- 影响：它保护的是**异构票据的字段定位方法**，不是“跨多张单据形成可核验证据链”。
- 风险：中低到中；如果我们把“bbox 定位”作为核心，需要说明与语义锚点方案的差异，并避免只做 OCR 坐标抽取。

### 8. `CN121639298A`：开票前风险规则

- 申请日：2025-12-10；公开日：2026-03-10；状态 Pending。
- 权利要求 1：监听发货结算/收货确认事件；获取结算数据；用预设风险规则校验；通过后调用税局乐企平台开票；对销项发票做事后风险分析并存入发票池。
- 影响：它覆盖“业务结算数据 → 风险规则 → 开票 → 事后风险”的链路，但不覆盖三单匹配和字段级证据归因。
- 风险：中低；作为“发票风险防控”相邻专利记录即可。

## 对项目叙事的直接影响

| 原先可能的写法 | 现在的判断 |
|---|---|
| “我们做三单匹配” | 不能作为创新点；国内已有授权专利和商业系统权利要求 |
| “我们做数电票结构化直读” | 不能单独作为创新点；已有 XML 存储、可视化、ERP 发票池相关专利 |
| “我们用 OCR/查验提高效率” | 不能作为核心创新；合思权利要求已把 OCR + 查验写进系统 |
| “我们用 AI 做异常检测” | 高风险；Oracle 及国内相邻专利均已覆盖“模型/规则 + 异常” |
| “我们做字段级 bbox 证据链” | 仍可能是差异点，但必须证明不是普通 OCR 坐标展示，且要避开语义锚点专利 |
| “我们做规则 + LLM + 人工复核” | 单独讲也危险；`CN122416469A` 已把这一组合写得很具体 |

## 还能站住的差异点（待进一步验证）

以下不是结论，而是下一轮应让专利代理人/技术负责人验证的候选：

1. **证据依赖图**：把“结论—规则/模型判断—字段值—原始单据坐标—人工复核”建成可查询的依赖关系，而不只是展示 bbox。
2. **矛盾归因**：不仅分类差异，还能给出“哪个字段、哪条业务规则、哪份单据、哪次修订导致差异”的可复核链条。
3. **跨单据字段级对齐**：在订单、收货、发票、付款之间建立字段级对应关系，并保留冲突版本和证据来源。
4. **人机协同的可审计决策**：模型建议、规则命中、人工修改和最终结论之间的版本化关系，能支持复核和追溯。
5. **结构化电子凭证的异常传播**：当上游字段变化时，定位受影响的下游单据、凭证和报表，而不是只对单张发票做异常评分。

这五条必须逐条做“现有技术检索 + 权利要求对比”，不能直接写进参赛材料当作已成立的新颖点。

## 检索与证据边界

- 本轮中文检索命中 49 条公开记录，但其中包含大量关键词误命中（如人脸识别、彩票、票务、股票路由），不能把 49 当作“相关专利数”。
- 8 件已读取首项权利要求；其余仅元数据/摘要级，未读全文。
- Google Patents 的 `Active/Pending` 是时间线状态，不是国知局官方登记簿；本轮未核年费、权利转移、审查修改、无效和诉讼。
- 国知局官方检索系统在当前网络环境下未能稳定打开；本轮使用可访问的中国专利全文页完成初筛。正式 FTO 必须回到 CNIPA/专业数据库复核。
- 本文件不是法律意见；是否落入某权利要求，需要按“全面覆盖原则”逐项比对，并由专利代理人出具意见。
