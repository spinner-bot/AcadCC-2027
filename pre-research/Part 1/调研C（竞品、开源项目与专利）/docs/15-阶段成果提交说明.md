## 可以交给负责人的五条结论

1. **开源侧没有发现生产级的“三单匹配 + 归因”完整项目。** 中英双语检索方向一致；但这是 GitHub 关键词检索结论，不能外推到整个市场。
2. **存在 1 个高度重合的公开 demo。** 已完成源码级核验：它有三单匹配、容差、`riskReason`、推理链和 bbox 溯源，但未发现数电票 XML/OFD 直读和账套对接。正确表述是“规则级解释 + 过程留痕，尚未到证据驱动归因”。
3. **商业竞品已完成 6/13 家公开页核验。** Oracle、Medius、每刻、合思有直接支持证据；金蝶、汇联易公开页关键项未见说明。P0 已查看 48/117 格，其中有直接支持证据 8/117 格。不能据此写“国内厂商能力弱”。
4. **专利侧已发现正面撞车。** 中国检索命中 49 条公开记录，已读 8 件首项权利要求：`CN112131470B` 已授权，覆盖发票—货物清单自动匹配和结算；合思 `CN116596607A`（Pending）把“应付三单匹配 + 发票查验 + OCR + 预制发票确认 + 发起开票”写进 claim 1；长飞 `CN119850353B` 已授权，覆盖数电发票行级匹配 + 价格容差 + 应付发票。
5. **原选题必须收窄。** “AI 辅助财务凭证与业务数据交叉核验”作为大方向可以继续讨论，但不能把“三单匹配”“数电票直读”“OCR + 查验”“规则 + LLM + 人工复核”当成单独创新点。当前相对可争的空间是：跨单据字段级证据依赖图、矛盾归因、人在环的可审计决策。

## 六家已核厂商的一句话结论

| 厂商 | 结论 | 证据 |
|---|---|---|
| Oracle | 2/3/4-way 匹配、容差、重复发票检查均有官方文档；企业级基线 | E001、E002（A） |
| Medius | AI 采集 + 三方匹配（PO/收货/合同）已产品化；归因未见说明 | E003、E004（B） |
| 汇联易 | 费控、报销、电子档案强；公开产品页未见“三单”原文，属相邻产品 | E005（B） |
| 每刻 | 明确写“采购订单、入库单、发票自动三单匹配”，并做明细逐行匹配、查验、应付、档案 | E007（B） |
| 合思 | 以“四单匹配”呈现，另有应付台账、采购对账、档案；四单范围待确认 | E008（B） |
| 金蝶 | 公开产品页本轮未见“三单”原文；不能判定不支持，需产品手册/售前 | E006（B） |

> 证据等级：A=官方文档，B=厂商官网自述。B 级只能证明“厂商这样宣称”，不能证明“已实测”或“客户已上线”。

## 尚未完成、不能包装成结论的部分

- 商业竞品仍有 7 家未核（SAP、Basware、Coupa、Tungsten、Tipalti、用友、云砺）；金蝶、汇联易公开页关键项未见说明，需产品手册、售前或试用。价格仍无同口径成交价，客户数量与案例主要是厂商自述，尚缺独立证据。
- 中国专利只读了 8 件首项权利要求；未核国知局官方登记簿、审查档案、同族、年费、权利转移、无效/诉讼。
- 美国专利的权利要求未逐条读完，尤其是 Oracle `US11915195B2` 的完整权利要求。
- “国内厂商 AI 归因弱”仍是推断，禁止写入正式材料。
- “没有专利风险”“竞品都不做归因”“市场没有同类产品”都不能写。

## 建议负责人做的三个决定

1. **是否接受当前阶段结论**：三单匹配与数电票行级匹配已是现有技术，原选题需要收窄。
2. **是否批准下一轮专利核查**：优先 `CN116596607A`、`CN119850353B`、`CN122416469A` 的完整权利要求与审查档案。
3. **是否把选题重心转向证据链**：以“跨单据字段级证据依赖图 + 矛盾归因 + 可审计人机协同”为候选差异点，而不是继续包装三单匹配。
